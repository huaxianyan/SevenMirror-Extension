# 通知历史与搜索

弹窗分三页：未读、历史、设置。这个文档说明三者各自装什么、已读怎么判定、历史留多久。

## 未读与历史

一条通知只有两种状态：**未读**或**已读**。没有第三份列表，也没有第二套存储。

- 未读＝本浏览器收到、且还没有被打开过的通知。角标统计的也是这一批。
- 已读＝打开过详情，或点了「全部已读」。已读通知立刻离开未读页，进入历史页。
- 手机已经清除的通知，无论此前是否读过，一律按已读处理：它已经无法回复或清除，挂在未读页只会出现点了没反应的条目。

「全部已读」对所有未读执行与打开详情相同的标记，因此角标、未读页和历史页不会互相矛盾。

## 保留上限

历史最多保留 **200 条**，按接收时间从旧到新丢弃。上限在写入路径上执行，不依赖有人打开弹窗才清理。

## 关闭历史

设置页的「保留通知历史」默认开启。关闭后：

- 手机已经移除的记录会被清掉，不再出现在历史或搜索里。
- 手机仍在显示的通知照常保留，因为回复与清除还需要它。
- 未读不受影响，只是不再积累已读记录。

## 搜索

搜索框同时覆盖未读与历史，结果按「未读」「历史 · 日期」分组，上方给出总条数与未读条数。

- 只匹配通知的标题与正文，**不匹配应用名**。
- 匹配为不区分大小写的子串比较，不做分词。
- 搜索在本机完成，不会向服务端或手机发起请求。

## 清除历史

历史页的「清除历史」删除手机已经移除的记录。手机仍在显示的通知不能在这里删：删掉它会同时丢掉回复与清除的入口。

## 数据落在哪里

历史就是本机的通知记录，存在扩展自己的 IndexedDB 里，不额外复制一份。解除配对会连同这份记录一起清空，不需要单独清理。

正文是否落盘跟随每条通知发送时的内容：手机端关闭了某应用的正文同步，那条通知本来就没有正文，历史里也不会凭空出现。
