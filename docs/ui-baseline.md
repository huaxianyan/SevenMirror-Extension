# 界面基线

扩展的三个入口（弹窗、设置页、独立交互窗）与管理端使用同一套视觉规则。本文记录这些规则的位置，避免以后各页各改一套。

## 唯一来源

- 颜色、字体、字号、字重、圆角、顶栏、侧栏、卡片、按钮与输入框定义在 `src/shared/sevenmirror-theme.css`，内容对齐服务端管理端的 `internal/adminweb/assets/admin.css`。
- 弹窗与设置页只写各自的布局，不重新定义颜色或控件形状。弹窗另有一层密度别名，把旧变量名映射到公共 token。
- 详情面板的标记与样式在 `src/shared/notification-detail.css`，弹窗与独立交互窗共用。

## 间距节奏

设置页只有一套节奏，写在各页共用的布局规则里：

| 位置 | 间距 |
| --- | --- |
| 面板之间 | `1.25rem` |
| 区块标题到内容 | `1.25rem` |
| 页标题到说明 | `.4rem` |
| 相邻说明行 | `.5rem` |

卡片内的字段只由容器 `gap` 控制，不再叠加全局的输入框外边距。空的状态行与空列表不占高度。

## 悬停

公共主题把普通 `button` 当作主操作按钮，悬停会填充主色。列表行、底栏页签、图标按钮都是 `button`，因此各自用更高特异性的规则改成浅色调：

- 列表行：底色向主色混 6%，并加深边框。
- 底栏页签：不填背景，只加深文字；当前页签保持主色。
- 图标与返回按钮：使用同一层浅色调。

## 滚动

- 只滚正文：设置页的顶栏固定，只有 `.layout` 区域滚动；弹窗的顶栏、搜索框与底栏固定，只有 `#list-view` 与 `#detail-view` 滚动。整页滚动会让滚动条把通栏顶栏的右侧空出一条，看起来像 layout 坏了。
- 滚动容器本身要通栏：设置页的 `.layout` 铺满窗口宽度，滚动条才贴在窗口右缘；72rem 的栏宽收在内层 `.layout-inner` 上。把栏宽放在滚动容器上，滚动条就悬在页面中间。
- 滚动容器上设 `scrollbar-gutter: stable`，滚动条只占正文区域的右侧，且无论有没有滚动条正文宽度都不变。
- 独立交互窗是整页滚动，所以在 `html` 上留位。
- 弹窗用固定 `520px`（`--popup-height`）定高，不用 `max-height`、也不用 `100vh`：弹出窗口按内容定尺寸，`100vh` 和 `100%` 拿到的是 Chrome 当时量出来的那个小高度，内容一少列表就塌成几十像素，空状态一起被裁掉。顶栏右侧的按钮组固定 36 像素高，切换未读与历史时顶栏高度不变。

## 层级与控件

- 一个页面只有一个 `h1`，就是导航上那一项的名字；同一页里的第二个区块降为 `h2`，卡片内的块标题再降一级。三个层级依次是页标题 `2rem`、区块标题 `1.5rem`、卡片标题 `1.1rem`，全部 `600` 字重。此前「连接」页里「连接」与「设备」同为 `h1`、字号都是 `2rem`，读起来像两个页标题。
- 字重只有两级：正文 `500`，强调 `600`。`650`、`700` 在多数中文字体里会落到最粗的那一档，和 `600` 差出一整级。
- 控件高度统一 `36px`：图标按钮、返回按钮、主按钮、次按钮都一样。清空搜索的按钮是 `24px`，因为它落在 `40px` 高的输入框内部，再大就会顶到边框。
- 焦点环只在主题里定义一次（`3px` 实线 `--focus`）；弹窗不再自己写一条 `2px` 的。搜索框把输入框自身的 `outline` 去掉了，改用 `.search:focus-within` 给整个字段画环，否则聚焦时看不到任何反馈。
- 详情浮层的按钮直接用主题的 `button` 规则，那份文件只负责排版（一行按钮均分宽度之类），不再重复声明圆角、内边距、悬停与焦点。

## 侧栏

设置页侧栏是 `position: sticky`，它的偏移会被所在列高度夹住。短页面会让导航上跳，因此布局容器保留了至少一屏的高度。

## 通知页的分组

通知页按「读的人要先回答哪个问题」分组，不再是一个卡片一串开关：

| 卡片 | 内容 | 回答的问题 |
| --- | --- | --- |
| Android 来源 | 每台已授权设备的开关 | 谁在往这里发 |
| 提醒方式 | 新通知角标、浏览器通知 | 有新通知时怎么让人知道 |
| 显示内容 | 通知正文、应用图标和头像、保留通知历史 | 列表里看得到什么 |
| 提示音 | 通知提示音开关、试听按钮 | 有没有声音 |

卡片标题是名词短语，不用问句，也不用第二人称。开关下只在「关掉之后会怎样不明显」时补一行说明，目前只有「通知正文」与「保留通知历史」两行，都是「关闭后……」句式；其余开关不加说明，以免整页变成灰色小字堆砌。

卡片内部按设计稿的固定节奏，不跟随内容多少变化：

| 位置 | 间距 |
| --- | --- |
| 卡片内边距 | `16px` |
| 卡片标题到第一个开关 | `14px`（由列表 `gap` 提供，标题自身不再留外边距） |
| 开关之间 | `14px` |
| 开关行最小高度 | `44px`，不加分隔线 |

开关清单用 `display: grid; gap` 排版时，卡片标题也是一个网格项，标题的 `margin-bottom` 会和 `gap` 叠加成两倍间距，所以 `.option-list > h2:first-child` 把外边距归零。段落式的「通知快捷操作设置」链接要写成 `display: inline-block`：行内元素的竖直 `margin` 不参与排版，否则链接会贴着卡片底边。

## 提示音的取值方向

存储字段仍是 `silentNotifications`（`true` 表示静音，默认 `false`），界面这一层取反：开关「通知提示音」打开对应 `silentNotifications: false`。

- 只有界面文案与勾选状态反转，存储格式、默认值、后台播放判断都不变，升级不需要迁移。
- 旧的 `optionsSilentNotificationsTitle`（“静默浏览器通知”）已经不存在；改用 `optionsNotificationSoundTitle`（“通知提示音”）。这不是改名字而是换意思，只改键名、留着旧译文会让英文界面出现相反的说法。
- 试听按钮走独立的 `PREVIEW_NOTIFICATION_SOUND` 消息，不受这个开关影响：开关关着也能试听，它只是试听。
