# Device WebSocket Authentication Frame v1

Status: provisional (`0.1.0-dev`)

A client connects to `GET /v1/relay` over TLS and MUST send this frame as the
first WebSocket binary message within 5 seconds. Authentication secrets MUST
NOT appear in the URL, query string, cookies, or logs.

## Canonical encoding

Exactly 68 bytes:

| Offset | Size | Field |
| ---: | ---: | --- |
| 0 | 4 | ASCII magic/version `SNA1` |
| 4 | 16 | Workspace ID |
| 20 | 16 | Device ID |
| 36 | 32 | Device authentication token |

Workspace and device IDs MUST be non-zero. The token is generated by the
server with a CSPRNG during one-time-code registration. The server persists
only `SHA-256(token)` and returns the raw token exactly once to the device.
Clients MUST store it using platform-protected local storage.

A malformed or invalid frame closes the connection with one generic policy
violation response. The server does not disclose whether the workspace,
device, or credential was wrong. It clears its temporary token buffer after
the authentication attempt.

After successful authentication, every subsequent client data message MUST be
one bounded Encrypted Envelope v1 binary frame. The authenticated workspace and
device are bound to the clear Routing Header before ciphertext routing.

The server sends WebSocket Ping control frames every 30 seconds and closes a
connection that does not provide Pong/read activity within 75 seconds.

## Security boundary

This transport credential controls private-instance admission and routing; it
is not an E2EE identity key and cannot authenticate or decrypt business
payloads. TLS (`wss://`) is mandatory outside loopback because this initial
frame contains the bearer credential.
